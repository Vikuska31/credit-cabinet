# backend — ядро (Федя)

Java 21+, пока **без Spring**: вся бизнес-логика написана на чистой Java, Spring-слой (REST, JPA, конфигурация) добавляется следующим этапом.

## Что внутри (`src/main/java/ru/creditcabinet/backend`)

| Пакет | Назначение |
|---|---|
| `tariff` | Синтетический тариф, аннуитетный калькулятор, два расчёта, график платежей, цели и подсказки |
| `decision` | Решение по явным правилам: отказ / нужны сведения / одобрение / встречное предложение, с причинами |
| `application` | Заявка, состояния и переходы, черновик, отправка без дублей, уточнения, принятие, демо-выдача |
| `auth` | Вход по паролю (PBKDF2) и по кнопке демопрофиля, роли CLIENT/EMPLOYEE, профиль компании |
| `inquiry` | Запрос сотруднику по неясной цели «Другое» |
| `notification` | Уведомления клиенту и сотрудникам |
| `bank`, `application.DocumentCatalog` | Интерфейсы к мокам Вики и documents-service |
| `demo` | **Временные** демоданные в коде (зеркало `data/demo-profiles/profiles.json`) |

## Проверка без Maven

```bash
cd backend
javac --release 21 -d /tmp/cc-out $(find src -name '*.java')
java -cp /tmp/cc-out ru.creditcabinet.backend.ScenarioCheck
```

`ScenarioCheck` проходит все три демопрофиля, уточнение, встречное предложение, сбой источника и права доступа.

## Допущения, которые нужно утвердить

Числа тарифа в `tariff/Tariff.java` придуманы для прототипа: 100 тыс. – 10 млн ₽, 6–60 мес., 21% годовых, комиссия 1%, допустимая долговая нагрузка 35% от среднемесячных поступлений, просрочка в прошлом не больше 30 дней, бизнесу не меньше 6 мес.
Учётка сотрудника `employee` / `employee1234` — тестовая, в `profiles.json` её нет.

# Умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого и микробизнеса (хакатон Альфа-Банка, кейс «Умный кредитный кабинет предпринимателя»). Клиент выбирает кредитный продукт, подаёт заявку и получает результат в личном кабинете, а банковская часть проверяет данные, считает оценку риска и принимает решение. Состояние заявки сохраняется и меняется последовательно, статус виден клиенту.

## Назначение

- Личный кабинет клиента: подбор продукта, расчёт, мастер заявки из четырёх шагов, документы, статус заявки.
- Обработка заявки на стороне банка: проверка данных, обогащение из имитированных источников (БКИ, реестр, счета), скоринг, кредитное решение с объяснением.
- Четыре исхода: одобрение, одобрение на иных условиях, запрос уточнения (включая недостающие документы), отказ.
- Опциональный ИИ-помощник (Qwen 3, через Ollama) — не обязателен, не принимает решений, не изменяет заявки.

## Архитектура

```
Браузер → frontend (nginx + React, порт 3000)
            → backend (Spring Boot, порт 8080) — заявки, статусы, скоринг, решение
                → mocks (FastAPI, порт 8001) — имитация БКИ, реестра, счетов
                → documents-service (FastAPI + SQLite, порт 8002) — хранение документов
                → ai-service (FastAPI, порт 8003, опционально) — помощник на Qwen 3
            → PostgreSQL (порт 5432) — хранилище backend
```

Подробная схема: [docs/architecture.md](docs/architecture.md). Описание API: [docs/api.md](docs/api.md), OpenAPI: `docs/openapi/`. Диаграмма состояний заявки: [docs/state-diagram.md](docs/state-diagram.md). Модель данных: [docs/data-model.md](docs/data-model.md).

## Требования к окружению

- Docker Desktop (с включённым WSL2 на Windows) или Docker Engine + Docker Compose.
- Свободные порты: 3000, 8001, 8002, 8080, 5432 (и 8003, если включаете ИИ).
- Для ИИ-помощника дополнительно: [Ollama](https://ollama.com), установленная **на компьютере**, не в Docker, и загруженная модель `qwen3:4b-instruct-2507-q4_K_M` (`ollama pull qwen3:4b-instruct-2507-q4_K_M`). Рекомендуется от 8 ГБ свободной оперативной памяти. Без Ollama кредитный сценарий работает полностью, ИИ-помощник не обязателен.

## Запуск

```bash
git clone https://github.com/Vikuska31/credit-cabinet.git
cd credit-cabinet
cp .env.example .env
docker compose up --build -d
```

Первая сборка занимает до 10–15 минут (backend на Java собирается дольше остальных). Проверка, что всё поднялось:

```bash
docker compose ps
```

Все сервисы (`db`, `mocks`, `documents-service`, `backend`, `frontend`) должны быть в статусе `running` или `Up`.

Сайт: **http://localhost:3000**

Остановить проект: `docker compose down`. Хранилище данных backend — в оперативной памяти: **при перезапуске контейнеров все заявки и сессии сбрасываются**. Это сознательное упрощение прототипа.

### Запуск с ИИ-помощником (опционально)

1. Установить и запустить Ollama, загрузить модель: `ollama pull qwen3:4b-instruct-2507-q4_K_M`.
2. В `.env` установить `AI_ENABLED=true`.
3. Запустить с дополнительным профилем:
   ```bash
   docker compose --profile ai up --build -d
   ```

Без Ollama или без флага `--profile ai` сервис `ai-service` просто не поднимается, а кредитный сценарий работает в обычном режиме.

## Переменные окружения

Полный список с значениями по умолчанию — в [.env.example](.env.example). Ключевые:

| Переменная | Назначение |
|---|---|
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | Подключение к PostgreSQL |
| `STAFF_LOGIN`, `STAFF_PASSWORD` | Учётная запись сотрудника банка |
| `DOCUMENTS_SERVICE_TOKEN` | Служебный токен между backend и documents-service |
| `AI_ENABLED` | Включает/выключает ИИ-помощника (по умолчанию `false`) |
| `LLM_BASE_URL`, `LLM_MODEL_NAME`, `LLM_PROVIDER` | Подключение к Ollama (нужны только при `AI_ENABLED=true`) |

Реальные секреты в `.env` не попадают в репозиторий, в нём хранится только `.env.example` с примерами.

## Тестовые учётные записи и данные

Все данные синтетические, лежат в `data/demo-profiles/profiles.json`.

| Профиль | Логин | Пароль | Особенность |
|---|---|---|---|
| ИП новичок | `demo.ip` | `demo1234` | Нет кредитной истории, документов нет |
| ООО с историей | `demo.ooo` | `demo1234` | Кредитная история без просрочек, финансовая сводка уже приложена |
| Риск просрочки | `demo.risk` | `demo1234` | Текущая просрочка 18 дней, высокая долговая нагрузка |

На экране входа есть кнопки демопрофилей — они подставляют вход автоматически, вводить логин и пароль вручную не обязательно.

Сотрудник банка: `employee` / `employee1234`, вход на том же экране, отдельной ссылкой.

## Пошаговый сценарий проверки

1. Открыть **http://localhost:3000**, войти по кнопке демопрофиля «ООО с историей».
2. На странице «Кредиты» выбрать цель (например, «Оборудование»), сумму до 3 млн ₽ и срок, посмотреть расчёт.
3. Нажать «Подобрать кредит» → пройти мастер заявки: параметры, данные компании (подставлены из карточки клиента), документы (сводка находится автоматически, нажать «Приложить найденные документы»), подтвердить согласие.
4. Отправить заявку. Статус должен смениться на «На рассмотрении», затем — на решение (ожидается одобрение).
5. Открыть заявку в разделе «Заявки», убедиться, что видна история событий, и принять условия.
6. Выйти, войти под профилем «Риск просрочки», повторить шаги 2–4 — ожидается отказ или иные условия, с объяснением причины.
7. (Опционально) Войти под профилем «ООО с историей», выбрать сумму больше 3 млн ₽ — система должна запросить дополнительные документы (декларация, бухотчётность, справка ФНС), а не одобрить заявку сразу.

Коллекция запросов для проверки API напрямую, без интерфейса: [postman/credit-cabinet.postman_collection.json](postman/credit-cabinet.postman_collection.json).

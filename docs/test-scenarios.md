# Сценарии проверки кредитного кабинета

Ожидаемое поведение для прототипа, согласованное Леной 25.10.2026. Тариф и данные синтетические. После сборки для каждого сценария записать результат («прошёл / не прошёл»), фактическое поведение и ссылку на дефект. До проверки не помечать сценарий пройденным. Правила — в [продуктовом документе](product-review.md).

Для сравнения демопрофилей использовать одинаковую заявку: **1 000 000 ₽, 24 месяца, «Товары и сырьё»**. Каждый прогон начинать с новой заявки или сброшенных демоданных.

| № | Действие | Ожидаемый результат |
|---|---|---|
| С01 · Вход | Ввести неверный, затем верный пароль; отдельно войти через демокнопку. | Ошибка допускает повторный ввод. Оба способа ведут в кабинет выбранной компании; данные компаний не смешиваются. |
| С02 · Профиль | Открыть аватар ИП. | Видны ФИО, форма бизнеса, название, ИНН, дата регистрации и ОКВЭД; кредитной истории в профиле нет. |
| С03 · Подбор | Выбрать оборудование и рекламу, указать одну сумму и срок. | Обе цели сохранены, расчёт содержит ставку, комиссию, платёж и общую выплату. Решение банка не обещается. |
| С04 · Два расчёта | Сравнить карточки; повторить на сроке 60 месяцев. | Вторая карточка сохраняет сумму, увеличивает срок и снижает месячный платёж; при 60 месяцах её нет. |
| С05 · Черновик | Начать заявку, заполнить часть полей, закрыть и открыть снова. | Открывается тот же шаг с прежними суммой, сроком, целями и ответами. |
| С06 · ИП | Подать базовую заявку без финансовой сводки; затем приложить её. | Банк запрашивает документ, не отказывает из-за его отсутствия. Проверка продолжается в той же заявке с прежним номером. |
| С07 · Повторный файл | Войти как ООО с историей и создать новую заявку. | Сводка из библиотеки предлагается с указанием периода; повторно загружать её не нужно. |
| С08 · Оборудование | Отправить заявку без документа о покупке; затем приложить подходящий файл. | Сначала видна причина блокировки. После счёта, предложения или договора со спецификацией отправка доступна. |
| С09 · Другое | Ввести понятную, непонятную и личную цель. | Предложенную категорию подтверждает клиент. При неясности остаётся ручной выбор/уточнение; личная цель не оформляется как кредитный отказ. |
| С10 · Просрочка | Подать базовую заявку через профиль «Риск просрочки». | Клиент получает объяснение результата без сырых банковских данных; сотрудник видит основание и источник. |
| С11 · Встречное предложение | Подать заявку с чрезмерным платежом, для которой допустим другой срок или сумма. | Видно сравнение исходных и новых условий и причину изменения; требуется явное принятие или отказ. |
| С12 · Сбой источника | Отключить тестовый источник банковских данных, отправить заявку и восстановить источник. | Статус «Проверка не завершена»; повтор работает в той же заявке. Сбой не становится отказом. |
| С13 · Права и дубли | Открыть чужую заявку, вызвать действие сотрудника и дважды отправить заявку. | Чужие данные и действия сотрудника недоступны; повтор не создаёт вторую заявку. |
| С14 · Сумма выше порога | Запросить 5 млн ₽ на ремонт для ООО. | Видны документы для суммы свыше 3 млн ₽ и два подтверждения по ремонту. Без подтверждений ремонта отправка заблокирована; остальные файлы можно дослать. |
| С15 · Граница порога | Сравнить 3 000 000 ₽ и 3 000 001 ₽. | Расширенный пакет нужен только во втором случае. |
| С16 · Запуск | По корневому README запустить проект и пройти С01, С03, С06/С07 и С10. | Все сервисы доступны, сквозной путь проходит через интерфейс и сервер, README содержит тестовые входы. |

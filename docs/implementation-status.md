# Состояние реализации — 26.10.2026

Основа: origin/main 2678e08; текущая feature/ai-assistant обновлена без изменения main.
Включены новые демо-PDF/профили Вики и продуктовые документы Лены.

## Реализовано

- Python/FastAPI AI-сервис с Qwen через OpenAI-совместимый HTTP API, JSON Schema, строгой валидацией, проверкой цитат и чисел, таймаутом и ограничением параллельности.
- Классификация пяти бизнес-категорий, нескольких целей, уточнений, личных и неподдерживаемых назначений.
- Java AI-фасад: авторизация, минимальный контекст, повторная валидация, закрытый перечень действий, серверные финансовые пояснения, режим без AI.
- Настоящие вход/профиль, серверные тарифы/расчёты, сохранение и восстановление черновика, документы и отправка, принятие/отклонение и уточнения.
- Подтверждение AI-предложений пользователем; ни один AI-запрос не изменяет заявку.
- Библиотека PDF: защищённый Java-прокси, сервисный токен, владение компанией, загрузка, версии, SQLite и файлы на диске.
- Минимальный кабинет сотрудника для отправленных заявок, запросов уточнения и ответов по цели.
- Compose, локальный запуск без Docker, документация и экспорт OpenAPI.

## Перед демонстрацией AI

1. Запустить реальную Qwen в Ollama/vLLM и настроить окружение по [ai-service/README.md](../ai-service/README.md).
2. Запустить кабинет с AI и выполнить opt-in набор RUN_QWEN_EVAL=1. Структурная валидация не заменяет семантическую оценку модели.
3. Повторить браузерный сценарий мобильной версии: npm run test:e2e -- --grep lower-payment.
4. В окружении с PostgreSQL/Docker выполнить соответствующие интеграционные проверки.

Полный порядок запуска и API: [ai-integration.md](ai-integration.md).

## Исправление локальной недоступности AI

Qwen3 8B возвращала HTTP 500: не удалось выделить CPU_REPACK-буфер около 3,1 ГБ.
Локальный .env переключён на qwen3:4b-instruct-2507-q4_K_M, таймауты модели/Java 60/65 секунд,
параллельность 1. Точное имя модели закреплено также в примере конфигурации и Compose.
Схема передаётся и в промпте, и в response_format; для классификации схема генерации
запрещает непустые категории/цитаты при личной или неоднозначной цели. Валидация после генерации сохранена.
После изменения .env текущий локальный запуск нужно перезапустить; тестовые заявки memory-режима при этом исчезнут.

26.10 воспроизведён OVERLOADED при одновременном запросе из двух виджетов. Добавлена ограниченная
очередь на один запрос; ожидание входит в общий таймаут. При повторном анализе фронтенд очищает
старую ошибку и показывает обработку, а при недоступности различает причины.
Для цитат восстанавливается только регистр из исходного текста; исправленные слова/числа не принимаются.
В генерации помощника закреплены связь статуса с уточняющим вопросом и пустые поля личных целей.
Неясный запрос получает подсказку о возможностях помощника вместо сообщения об отсутствующем объекте.
Frontend build и lint после этих изменений прошли; браузерная проверка этих изменений не запускалась.
Дополнительная тестовая JVM сначала не стартовала из-за лимита виртуальной памяти Windows (1455).
После выгрузки модели из памяти и уменьшения памяти тестовой JVM обе сквозные проверки прошли.
Рабочий кабинет и его заявки во время проверки не перезапускались.

Перед созданием PR ветка обновлена до main 2678e08 без конфликтов.
Повторно прошли Java-регрессия (12 успешных тестов, 4 PostgreSQL-проверки пропущены) и 3 теста документов.
